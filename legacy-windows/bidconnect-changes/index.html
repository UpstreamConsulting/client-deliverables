BidConnect: making a change

Changes now go through a branch and a pull request. Claude Code does the git; you say the sentences.

To make a changeFour sentences, in order. Copy each one into Claude Code.

1

Start

Start a new branch called name and make this change: what.

Give the branch a short name, like fix-zone-rates, then describe the change the way you would to a person.

2

Push and preview

Push it and give me the preview link.

Vercel emails you the preview link a couple of minutes later. It needs your Vercel login. Try the change there before you send it on.

3

Send it for merge

Open a pull request.

Claude opens it and gives you the link to the pull request page on GitHub.

4

Merge

Open the pull request page and look at the box at the bottom.

Green "Merge pull request" button: click it, then Confirm. The live app updates within minutes.

"Review required" with Levi's name: you are done. Levi reviews and merges, same day this week.

What to watch for

The two endings on the pull request page

Green buttonNobody else needs to look. Click Merge pull request, then Confirm.

Review requiredLevi is on it. Nothing more to do; you will see his approval on the same page.

If Claude says the push was refused

The message looks like GH013: Repository rule violations found. It means the change tried to go straight to the live branch. Nothing is lost. Type this and carry on from step 3:

Put this on a branch and open a pull request.

Which changes wait for Levi

  • Sign-in and signing
  • Database changes
  • The paid Claude call
  • Environment and deploy settings
  • Connector credentials

Everything else merges on its own: screens, pricing, costing, zones, proposal output, the gallery, tests.

To ask for something

For now, email Levi, or open an issue on the repository: github.com/legacy-windows/legacy-estimator/issues, then New issue. Say what you want and why. A request card inside Claude is coming later.
